# AGENTS.md — Guidance for AI Coding Agents

## Project Overview

`tfrmt` is an R package that creates a framework to store and apply display metadata to Analysis Results Datasets (ARDs). It allows users to define table format and styling without the data, and later apply the format to the data. The primary output format is `gt` tables.

## Repository Structure

```
R/              — Package source code
tests/testthat/ — Unit tests (testthat edition 3, including snapshot tests)
man/            — Documentation (generated by roxygen2, do not edit manually)
vignettes/     — Package vignettes (Rmd files)
data/           — Package datasets
data-raw/       — Scripts to generate package datasets
inst/           — Installed files (e.g., example JSON templates)
pkgdown/        — pkgdown site configuration
```

## Development Workflow

### Building and Checking

```r
# Install dependencies
devtools::install_deps(dependencies = TRUE)

# Run R CMD check (the primary CI check)
devtools::check()

# Build documentation (regenerates man/ and NAMESPACE)
devtools::document()
```

### Running Tests

```r
# Run all tests
devtools::test()

# Run a specific test file
testthat::test_file("tests/testthat/test-apply_tfrmt.R")
```

Tests use **testthat edition 3** with snapshot testing. If you change output formatting, you may need to update snapshots:

```r
testthat::snapshot_review()
```

### CI

The GitHub Actions workflow `.github/workflows/R-CMD-check.yaml` runs `R CMD check` across multiple OS/R-version combinations. PRs target the `main` branch.

## Coding Conventions

- **Tidyverse style**: Follow the [tidyverse style guide](https://style.tidyverse.org/).
- **Roxygen2 documentation**: All exported functions must have roxygen2 documentation with `@param`, `@return`, and `@examples` tags. Use `markdown = TRUE` in roxygen comments.
- **Tidy evaluation**: The package uses rlang tidy evaluation extensively (`!!`, `!!!`, quosures). Column references in user-facing functions are typically passed as bare names via `vars()` or tidyselect semantics.
- **Piping**: Use the magrittr pipe (`%>%`), not the base R pipe (`|>`).
- **S3 methods**: Many internal operations dispatch via S3 (e.g., `apply_frmt`, `as_json`). Follow existing patterns when adding new format types.
- **No base R pipe**: The package supports R >= 4.2 but uses magrittr for consistency with the existing codebase.

## Key Concepts

- **`tfrmt` object**: The core specification object that holds all table formatting metadata (column plan, body plan, row group plan, etc.).
- **`body_plan`**: Defines how values are formatted (via `frmt`, `frmt_combine`, `frmt_when`).
- **`col_plan`**: Defines column ordering and spanning structure.
- **`row_grp_plan`**: Defines row grouping and labeling behavior.
- **`frmt` / `frmt_combine` / `frmt_when`**: Value formatting specifications that can be combined and made conditional.
- **ARD (Analysis Results Dataset)**: The input data format — a long-format dataset with columns for group, label, column, parameter, and value.

## Testing Guidelines

- Write tests for all new exported functions and significant internal changes.
- Use `testthat::expect_*` functions; prefer `expect_equal()` over `expect_identical()` for numeric comparisons.
- Snapshot tests (in `tests/testthat/_snaps/`) capture printed output and error messages. Update them intentionally.
- Test files should mirror source file names: `R/foo.R` → `tests/testthat/test-foo.R`.

## Dependencies

- Do not add new hard dependencies (`Imports`) without strong justification.
- Suggested packages (`Suggests`) are acceptable for vignettes, tests, and optional features.
- The package depends on `gt` (>= 1.1.0) for table rendering.

## Common Pitfalls

- **NAMESPACE**: Never edit `NAMESPACE` directly — it is generated by roxygen2. Run `devtools::document()` after adding/removing exports or imports.
- **man/ pages**: Never edit `.Rd` files directly — they are generated from roxygen comments.
- **Quosure handling**: Column references passed by users are captured as quosures. Use `rlang::eval_tidy()`, `rlang::as_name()`, etc. for manipulation.
- **Snapshot tests**: Changes to formatted output (print methods, error messages) will cause snapshot test failures. Review and accept intentional changes.
